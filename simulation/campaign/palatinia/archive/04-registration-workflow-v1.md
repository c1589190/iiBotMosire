# 玩家报名接收与秘书工作区初始化流程

> 适用范围：《七柱之下：败退之后》
> 本流程使用现有 MCP 工具，不冒充尚未实现的“报名草稿硬确认”状态机。

## 一、流程总览

```text
玩家私聊秘书
  → 提交原始报名表
  → 秘书整理、去重、指出矛盾
  → 秘书把完整整理稿回给玩家
  → 秘书生成 6 位确认码
  → 玩家明确回复“确认报名 <确认码>”
  → 秘书才调用 secretary_post_create
  → 创建 PRIVATE 报名推文，状态 PENDING_APPROVAL
  → GM 通过 tf_post_list / tf_post_get 读取
  → GM 审核、合理化、解决职位冲突
  → GM 用 tf_gm_secretary_dispatch 初始化对应秘书工作区
  → 秘书获得玩家角色卡、世界基础资料、开局任务与 GM 约束
  → 玩家开始正式游戏
```

## 二、秘书侧的强制规范

1. **不得直接提交原始报名表。**
   - 玩家第一次发来的文本只是原料。
   - 秘书必须整理成结构化报名稿，检查缺失项、明显矛盾和超权限职位。

2. **必须让玩家确认。**
   - 秘书回给玩家一份完整整理稿。
   - 同时生成六位数字确认码，例如 `482913`。
   - 要求玩家只回复：
     ```text
     确认报名 482913
     ```
   - 玩家改任何关键内容，秘书必须重新出稿并换新确认码。
   - 未收到完全一致的确认字符串，不得创建报名推文。

3. **确认后才可创建推文。**
   - 使用 `secretary_post_create`。
   - `visibility=PRIVATE`。
   - 标题格式：
     ```text
     帕拉丁报名｜<称呼>｜<QQ后四位>
     ```
   - 正文应包含规范化报名表，并在末尾记录：
     ```text
     玩家已确认：是
     确认方式：私聊精确回复“确认报名 <六位码>”
     ```
   - 不批准、不发布、不声称已被录用。
   - 创建成功后只向玩家返回 `postId`、`status`、`revision`。

4. **禁止事项。**
   - 禁止秘书批准自己的报名推文。
   - 禁止把报名推文发到公开群。
   - 禁止替玩家填写“确认”。
   - 禁止同时提交重复报名；同一玩家同一版本只允许一条待审报名推文。

```text
【帕拉丁报名整理稿】

首选职位与地点：

法权身份：

出身履历：
两项资源：
两项约束：
可调动武力：
合法权限：
公开目标：
私人目标：
秘密（仅GM）：
对古比奥“善意撤退”的看法：

```

## 四、GM 审核清单

GM 收到 `PRIVATE + PENDING_APPROVAL` 报名推文后：

1. **角色可行性**
   - 职位是否存在；
   - 法权身份是否能任该职；
   - 年龄、履历和恩主关系是否合理；
   - 是否与时代、财政、军制和行政逻辑冲突。

2. **权力上限**
   - 地方官不得开局自行调动军团；
   - 中央基层官员不得拥有独立领地与私兵；
   - 基层军官不得越过军团指挥链；
   - 资金、兵力和情报必须与职位匹配。

3. **玩家冲突**
   - 同一城市、同一军团、同一职位是否重复；
   - 两名玩家是否被安排成必须互相消灭才能开局；
   - 是否需要把一个职位拆成正副、上下级或相邻辖区。

4. **合理化**
   - 调整官职名称、辖区大小、兵力、预算和债务；
   - 把“无限资源”改成有条件、可撤销的权限；
   - 把秘密改写成可被调查、会留下痕迹的事实；
   - 给角色增加至少一项现实约束。

5. **开局钩子**
   - 每名角色至少获得：
     - 一个必须处理的麻烦；
     - 一个可以争取的盟友；
     - 一个不能公开的弱点；
     - 一条与主线相连的具体线索。

## 五、审核通过后的秘书工作区初始化

GM 使用 `tf_gm_secretary_dispatch` 写入以下文件，禁止覆盖已有文件：

```text
player/world-basics.md
player/character-sheet.md
player/opening-orders.md
player/contacts.md
gm/registration-review.md
gm/secret-notes.md
```

### `player/world-basics.md`

给该角色职位相关的世界常识：

- 帝国与西境局势；
- 角色所在城市/部队；
- 当前季节、粮食、军饷、道路和驻军情况；
- 角色应当知道的公开势力与派系；
- 不包含其他玩家隐私和 GM 隐藏真相。

### `player/character-sheet.md`

审核后的正式角色卡：

- 姓名/称呼；
- 正式官职或军职；
- 法权身份；
- 上级、下属、恩主、政敌；
- 辖区和部队；
- 可调动人力、武装、资金和信息；
- 硬约束与债务；
- 公开目标、私人目标；
- 玩家确认过的秘密摘要（不写不应让玩家看到的 GM 版本）。

### `player/opening-orders.md`

开局必须处理的两到三个任务：

- 例如：冬季军粮征发、旧领主清算、税册重编、逃兵追捕、神庙抗议、火器试射、边境走私、卡普亚通道护送。
- 每项任务写明：
  - 上级要求；
  - 现实障碍；
  - 可动用的资源；
  - 失败的直接后果；
  - 可能的交易对象。

### `player/contacts.md`

角色已知的人脉与机构：

- 上级与同僚；
- 地方显贵；
- 神庙代表；
- 商人、包税人、粮商；
- 军队联系人；
- 不泄露其他玩家的秘密。

### `gm/registration-review.md`

GM 内部审核记录：

- 原始申请摘要；
- 做了哪些合理化；
- 批准的权力边界；
- 与其他玩家的关系/冲突；
- 后续剧情钩子。

### `gm/secret-notes.md`

仅 GM/秘书工作区可见的隐藏事实与风险：

- 玩家秘密的真实版本；
- 可能暴露秘密的调查路径；
- 角色当前的敌人和债务；
- 触发事件的条件；
- 不应在玩家未调查前泄露的内容。

## 六、审核结果通知

初始化完成后，GM 应通过一条简短的 `PRIVATE` 通知或秘书回复告知玩家：

- 报名已受理；
- 正式角色与辖区；
- 需要补充或接受的调整；
- 开局第一项任务；
- 下一次提交行动的格式。

报名推文本身不得直接视为已经录用；真正生效的是 GM 初始化后的角色卡与工作区材料。

## 七、当前工具限制

现有宿主没有独立的“报名草稿确认状态机”。因此：

- 确认由秘书在私聊中核验精确字符串；
- 确认码由秘书生成并保存在会话上下文中；
- 这不是密码学级别的硬确认；
- 如后续需要像 `/确认 <draftId>` 那样的宿主级不可伪造确认，需要开发新的报名草稿工具或扩展状态机。

在开发完成前，本流程以“秘书不得在确认前创建报名推文”为操作红线。
