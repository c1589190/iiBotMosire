# 06 发布前审稿清单

## 玩家可见性

- [ ] 是否出现 draftId/ticketId/postId/revision/contentHash/turnId/MCP/schema/workspace/文件路径？
- [ ] 是否出现状态枚举、异常类、工具回执、模型推理链？
- [ ] 是否出现 Markdown 标题/表格/代码块/反引号/加粗？
- [ ] 是否有测试、自动监控、环境、接口、系统说明等后台词？

## 可玩性

- [ ] 玩家能否在 10 秒内看出“发生了什么”？
- [ ] 是否有具体事实，而不是全是“可能/待定”？
- [ ] 是否给出 2–3 个下一步选项或明确自由行动入口？
- [ ] 是否一条消息只讲一个焦点？
- [ ] 是否超过一屏、需要拆分？

## 交互

- [ ] 是否重复要求确认？
- [ ] 是否要求玩家阅读文件或理解版本？
- [ ] 是否重复发送同一结果？
- [ ] 是否混用秘书/GM/系统/NPC 口吻？
- [ ] 是否伤害玩家已经表达的主动性（如玩家已说“随便你”还继续追问非必要细节）？

## 安全与边界

- [ ] 是否泄露其他玩家/私密事实？
- [ ] 是否把 GM 私有信息写给玩家？
- [ ] 是否把系统公告伪装成世界事实？
- [ ] 是否在未确认时把行动写成已执行？

## 结论

任何一项不过：不发，退回重写。代码门禁只能检查机械项，语气与重点由审稿人负责。
