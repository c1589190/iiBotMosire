## 1. 目标

在单人维护、本地优先的部署中，提供一个 Java 21 + Maven 的可运行 QQ Bot：

1. 通过可替换 Adapter 接入 QQ（首期 NapCat / OneBot 11）；
2. 把配置中的 QQ 用户识别为玩家或推演；
3. 维护一个版本化世界：固定核心提示词 + 经批准的世界设定；
4. 让每个玩家在可见信息范围内与 Bot 多轮交流；
5. 在一个回合内接收并冻结玩家格式化决策；
6. 由中央 Agent 审核与推演所有决策，输出公开/私密结果；
7. 把每次接收、决策、冻结、推演、提交、发送和人工操作写入可重放事件流；
8. 可选地通过本地 MCP 让外部 Agent 观察并受控推进事件流。

## 4. 功能需求（FR）

### FR-1 账号与会话

- 启动时从配置读取 QQ 账号映射；未登记 QQ 用户不能进入 Agent。
- 同一个 QQ `user_id` 的私聊消息严格串行；不同用户可并发。
- 同一 NapCat 账号连接的事件必须带 `self_id`，用于多账号路由和去重键。

### FR-2 世界构建

- 核心提示词有版本与哈希；回合提交时记录实际使用的版本。
- 世界观由结构化事实/章节与叙述性文档组成，每条事实有稳定 ID 和可见性。
- 玩家/推演提交设定时生成 `SettingProposal`，不得直接修改当前世界。
- 设定通过后生成新 `WorldVersion`；历史回合仍指向旧版本。

### FR-3 玩家秘书对话与信息过滤

- 每个玩家在私聊中只与自己的**秘书子 Agent**交流；秘书会话按玩家隔离。
- 秘书不直接读取完整世界数据库；它通过 GM/中央推演 Agent 获取**已审查、已过滤**的 `InfoBrief`。
- 秘书向 GM 的提问/请求、GM 的过滤结果、秘书向玩家披露的内容均写事件，可审计。
- 玩家 Agent/秘书只拿到自己可见的 brief；其他玩家的私聊、决策和秘密不得进入其上下文。
- 秘书可以形成决策草案并自动调用 `decision_draft` 工具，但不能自行提交有效决策。
- 公共群只接收公开信息；是否允许玩家在群内交流待 Q8。

### FR-4 自然语言决策 + 工具结构化 + 硬确认

- 仅在回合 `OPEN` 状态接受决策。
- 玩家用自然语言与秘书讨论行动；秘书可调用 `decision_draft` 生成结构化 `DecisionDraft`。
- 秘书把 draftId、字段预览、回合号和过期时间回显给玩家。
- 只有玩家从**同一私聊账号**发送固定硬命令，例如 `/确认 <draftId>`，宿主才把该 draft 转为有效 `Decision` 并写入回合。
- 自然语言“确认/同意/提交”不算硬确认；其他玩家、群聊、外部 MCP 不能代替确认。
- 每个玩家每回合最多一个有效决策；确认新 draft 会覆盖未冻结的旧 draft，并记录版本。
- 冻结时形成不可变 `TurnSnapshot`，包含世界版本、提示词哈希、全部有效决策和随机种子。
- 过期/非法/重复决策均给出明确拒绝原因并写事件。

### FR-5 中央 GM/推演 Agent

- 每个玩家的秘书有独立私有上下文；GM 在向秘书发 brief 前完成审查和过滤。
- 冻结后由单一中央 GM Agent 处理整个批次，不能并发跑同一回合。
- 先做确定性校验，再做 LLM 推演；模型只提交 `AdjudicationProposal`。
- 提案必须通过 schema、实体引用、可见性、版本与大小校验；非法则拒绝且不落世界变更。
- 合法提案以单个 `TurnCommitted` 领域事件原子生效。
- 结果包含：公开叙事、每玩家私密结果、世界变化、下一回合可公开事件。
- 中央 GM 与裁判/推演的人工签核方式仍待 Q2 细化，但“玩家硬确认”不能被任何模式绕过。
- 失败可重试，但同一回合不会生成两份已提交结果。

### FR-6 出站消息

- 所有消息经统一 `OutboundPort`，由 Adapter 实施限速、分段和敏感内容检查。
- 发送结果区分 `SENT`、`FAILED_BEFORE_SEND`、`UNKNOWN`；`UNKNOWN` 默认不自动重试。
- 查询/发送超时、连接断开、`retcode != 0` 均需有可观测事件与用户可理解的失败提示。

### FR-7 事件流与恢复

- 事件类型、schema version、payload 与 correlationId 有明确契约。
- 进程启动时从事件流重建投影；发现非法事件/未知 schema 时 fail-closed，不静默跳过世界变更。
- 重复 QQ 消息、重复命令、重复 MCP 请求按幂等键去重。
- 崩溃后不得出现半提交回合；未完成出站转 `UNKNOWN` 或可审计待办。

### FR-8 外部 MCP 全功能总控

- 独立工具注册表与独立 MCP Server，不与 QQ 玩家/中央 Agent 的工具面混用。
- 用户已选择“全部功能”：外部 Agent 应能观察并控制**全部游戏事件流**。
- 工具面至少覆盖：状态/事件/回合/秘书/GM/设定/决策审查/outbox/不变量，以及对应游戏控制命令。
- 仍强制：身份、状态机、expectedRevision、幂等键、审计、玩家硬确认不可绕过。
- 默认关闭；启用时绑定 `127.0.0.1`，所有请求必须 Bearer 鉴权（不能仅靠隐藏路径）。
- 进程启停、QQ 角色配置、密钥管理、任意 shell 等非游戏事件流操作是否暴露待 Q9；建议不暴露。

## 5. 非功能需求（NFR）

- **可恢复**：重启后状态与事件最后一致；持久化写失败时 fail-closed。
- **可审计**：任何世界变更、决策、MCP 写操作都有事件与操作者来源。
- **可测试**：核心状态机纯函数化；QQ/LLM/MCP 都有契约测试端口。
- **安全**：密钥不落盘到仓库/日志/模型；角色与可见性不可由输入提升。
- **并发**：同一会话串行、同一回合中央推演单飞、不同玩家可并行。
- **性能**：v1 以几十玩家、单世界、每秒少量消息为目标；不预设高并发。
- **可运维**：健康状态、连接状态、当前回合、最近错误可通过只读工具/日志观察。

## 6. 验收的顶层场景

1. 玩家 A 私聊自己的秘书，秘书只使用 GM 提供的 A 可见 brief 回复；A 看不到 B 的私密事实。
2. 秘书把 A 的自然语言行动整理为 draft；A 发送 `/确认 <draftId>` 后才形成有效决策。
3. 仅说“同意/提交”不产生有效决策；其他 QQ 用户或外部 MCP 不能代替 A 确认。
4. A/B 在开放回合内各确认一份合法决策；冻结后中央 GM Agent 生成一份包含两份决策的推演。
5. 冻结后 C 再确认决策被拒；重复消息 ID 不重复入账。
6. 非法/过期中央提案被拒绝，世界版本不变，回合进入可重试失败态。
7. 服务器在“事件已写但 QQ 回复未发”处崩溃，重启后不重复执行世界变更；出站进入可审计状态。
8. 外部 MCP 可执行全部游戏事件流控制，但错误状态/过期 revision/重复幂等键被拒绝，且不能伪造玩家硬确认。

### 仍需用户确认

#### Q5. LLM 路由

- provider、base URL、模型名、tool calling、reasoning_content、上下文窗口；
- 建议玩家秘书与中央 GM 使用不同模型/档位：秘书重响应速度，GM 重推演能力；
- 在 P0 的三库编译 smoke 后给出具体候选再确认。

#### Q6. 单世界 / 多世界

- 建议 v1 单活跃世界；若要多世界，MCP 工具、存储分区、命令和秘书上下文都要增加 worldId。

#### Q8. 公共群的交互边界

- A（建议）：公共群只做公开信息/公告，Bot 不把群内普通聊天送入 Agent；玩家交流全走私聊。
- B：公共群允许多玩家公开发言，并进入“公共会话”记忆；私密信息仍走私聊。
- C：群内也可提交/确认决策；需要处理同一玩家身份、隐私与消息顺序。

#### Q9. 外部 MCP“全部功能”的边界

- A（建议）：全部**游戏事件流**控制 + 全量游戏事件观察；不提供进程启停、QQ 角色配置、密钥、任意 shell。
- B：还包括角色热更新/重载配置，但需本地 admin token、二次确认和审计。
- C：还包括进程生命周期；强烈不建议，违反“不得关进程”的上位红线。

## 8. 建议的第一纵向切片

P1 先实现一个端到端最小切片：

1. 单世界、单 Bot、两个配置玩家；
2. 私聊 + Fake QQ Adapter（公共群先只做 outbox 通道）；
3. 每玩家一个秘书 Agent（Fake LLM 驱动），GM 以过滤 brief 供信息；
4. 固定世界提示 + 静态公开事实；
5. 自然语言 → `DecisionDraft` → 玩家 `/确认 <draftId>` → `OPEN → LOCKED → ADJUDICATING → COMMITTED`；
6. Fake LLM 返回合法/非法推演提案各一条；
7. SQLite 事件回放、重复消息、硬确认负向测试；
8. 实际实现已扩展为 4 模块（connect / connect-agent / taskflow / app）；MCP 实现为 4 读 + 11 全游戏事件流写工具，非游戏运维权仍不开放。

此切片先证明秘书/GM 信息过滤、玩家硬确认和状态机，再向真实协议扩展。
