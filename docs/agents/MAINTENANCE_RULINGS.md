# 项目维护裁定台账

> **性质**：只收项目维护相关的用户裁定：文档系统、Skill、门禁、协作、环境、提交/归档。
> **不在这里写**：模块边界、事件/载荷、提示词语义、回合状态机、数据所有权等领域设计。
>
> 登记规则：新增条目用 `M-xxx`；原话逐字保留，注明日期、来源、影响、正本落点和状态。
> 被取代的条目不删，只改状态字段并指向取代者。
>
> 设计侧正本索引：[`docs/superpowers/DESIGN_RULINGS.md`](../superpowers/DESIGN_RULINGS.md)。

## M-001 文档系统采用 SimulatorMosire 最新分层格式

- **日期**：2026-10-24
- **用户原话（逐字）**：
  > 「项目文档格式使用隔壁SimulatorMosire最新更新的那个版本，所以你应该先搞出来项目文档体系，然后再进行项目实现调查」
- **分类**：项目维护（文档系统）
- **裁定**：
  1. 根 `AGENTS.md` 只做项目简介、常驻红线与索引，不堆长流程；
  2. 项目设计与项目维护分账；
  3. 使用唯一实时 `docs/agents/STATUS.md`，dated status 仅作历史快照；
  4. 建立 `.agents/skills/` 工程 Skill 入口与机械检查；
  5. 先完成文档体系，再给出实现调查。
- **当前正本**：`AGENTS.md`、`docs/AGENTS.md`、`docs/agents/STATUS.md`、`docs/agents/SKILLS.md`
- **状态**：有效

## M-002 没有 Maven 工程前，文档门禁不得要求 pom

- **日期**：2026-10-24
- **分类**：项目维护（验证）
- **裁定**：本轮只建立文档体系与调研，不初始化 Maven。`tools/check-docs.py` 必须支持 pre-Maven 阶段；
  不得为了“检查通过”伪造 `pom.xml` 或模块文件。
- **当前正本**：`tools/check-docs.py`、`docs/agents/VERIFICATION.md`
- **状态**：有效

## M-003 外部资料与本地事实分层记录

- **日期**：2026-10-24
- **分类**：项目维护（文档引用纪律）
- **裁定**：第三方 API 结论优先引用官方文档并保留 URL；本机上游库结论引用 `file:line` 与版本/提交；
  没跑过的真实联调写 `NOT_RUN`，不拿文档摘抄冒充运行证据。
- **当前正本**：`docs/AGENTS.md` §九、`docs/agents/VERIFICATION.md`
- **状态**：有效

## M-004 需要用户协同的外部步骤先停下等一轮

- **日期**：2026-10-24
- **用户原话（逐字）**：
  > 「你知道吗，遇到需要我协同的事，停下来等我整上一轮是很好的习惯，也许你该把这个规范记下来」
- **分类**：项目维护（工作流 / 协作 / 真实外部测试）
- **裁定**：
  1. 需要用户提供真实 QQ 操作、真实外部确认、凭据、人工观察或其他必须由用户完成的状态时，先停下，说明已知事实、风险和**本轮只需要用户做的一件事**；
  2. 等待用户回应后再继续，不把“等待”伪装成“自动继续”；
  3. 不用自测消息、脚本发送或占位账号冒充秘书/玩家回复；
  4. 真实外发前先说明目的与目标；不在用户未授权时连续发消息或改变外部状态；
  5. 阻塞时标 `WAITING_USER` / `BLOCKED`，不写 DONE。
- **当前正本**：`AGENTS.md` §2、`docs/agents/WORKFLOW.md` §七、本条目
- **状态**：有效
